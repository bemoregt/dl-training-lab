# Same Image Removal

파일명이 달라도 **내용이 같은 영상(GIF)** 을 찾아 하나만 남기고 정리하는 도구입니다.
단순 파일명/크기 비교가 아니라, 실제 프레임 이미지를 분석해서 "같은 영상이 재인코딩/리사이즈되어 다른 파일로 저장된 경우"까지 잡아냅니다.

## 왜 필요한가

커뮤니티/카페 게시판을 크롤링해서 GIF를 백업하다 보면, 같은 영상이

- 완전히 같은 파일로 여러 게시물에 재업로드되거나 (바이트 단위 동일)
- 화질/해상도만 다르게 다시 인코딩되어 재업로드되는 경우 (내용은 같지만 바이트는 다름)

가 흔합니다. 파일명 비교로는 후자를 절대 잡을 수 없어서, 실제 프레임 픽셀을 비교하는 방식이 필요합니다.

## 중복 제거 원리

3단계로 나눠서 정확도와 속도를 동시에 확보합니다.

### 1단계 — MD5로 완전 동일 파일 제거

모든 GIF 파일의 MD5를 계산해 그룹핑합니다. 해시가 같으면 바이트 단위로 100% 동일한 파일이므로, 오탐 없이 안전하게 그룹당 1개만 남길 수 있습니다.

### 2단계 — Perceptual Hash로 "같은 영상, 다른 인코딩" 탐지

1단계에서 걸러지지 않는, 내용은 같지만 바이트가 다른 파일(리사이즈/재인코딩/워터마크 추가 등)을 잡기 위한 단계입니다.

각 파일(정확히는 1단계에서 나온 고유 콘텐츠 그룹의 대표 파일 1개씩)마다:

- **첫 프레임**과 **중간 프레임**을 추출
- 각 프레임에서 두 종류의 해시를 계산
  - **dHash (difference hash)**: 8×9로 축소한 뒤 인접 픽셀의 밝기 증감 패턴(더 밝아졌는지/어두워졌는지)을 64비트로 인코딩. 리사이즈·재압축에 강함.
  - **aHash (average hash)**: 8×8로 축소한 뒤 평균 밝기보다 밝은 픽셀을 64비트로 인코딩. dHash와 다른 종류의 오탐을 걸러주는 보조 지표.

두 파일이 같은 영상인지는 **해밍 거리**(비트가 다른 개수)로 판정합니다. 실제 크롤링 데이터에서 확인해보면, 진짜 같은 영상끼리는 거리가 0~5(64비트 중)에 몰려 있고, 다른 영상끼리는 훨씬 멀리 떨어져 있어 임계값으로 뚜렷하게 갈립니다.

```
dhash1(첫 프레임) ≤ 6  AND  ahash1(첫 프레임) ≤ 6  AND  dhash2(중간 프레임) ≤ 8
```

세 조건을 모두 만족해야 같은 영상으로 판정합니다. 프레임을 2곳(첫/중간)에서 뽑는 이유는, 우연히 첫 프레임만 비슷한 서로 다른 영상(예: 같은 배경에서 시작하는 클립)을 걸러내기 위함입니다.

### 3단계 — 후보 쌍 추리기 (LSH 밴딩)

파일이 수천~수만 개면 모든 쌍을 비교하는 건 O(n²)이라 느립니다. 그래서 64비트 해시를 16비트씩 4조각으로 나누고, **한 조각이라도 값이 같은 파일들끼리만** 후보로 묶습니다(locality-sensitive hashing). 후보로 추려진 쌍에 대해서만 정확한 해밍 거리를 계산해 검증하므로, 전수비교보다 훨씬 빠르면서도 결과는 동일합니다.

### 4단계 — 클러스터링과 대표 파일 선정

Union-Find로 "A~B 유사, B~C 유사 → A/B/C는 한 그룹"처럼 전이적으로 묶습니다. 각 그룹에서는 **해상도(가로×세로)가 가장 큰 파일**을 남기고 나머지를 삭제 대상으로 표시합니다(화질 손실 없이 원본에 가장 가까운 파일을 보존하기 위함).

## 실제 적용 결과 (참고 사례)

네이버 카페 GIF 백업 폴더(9,965개 파일)에 적용한 예:

| 항목 | 개수 |
|---|---|
| 전체 GIF | 9,965 |
| 완전 동일 파일 (MD5 중복) | 2,088개 삭제 |
| 재인코딩된 동일 영상 (perceptual hash 중복) | 138개 삭제 |
| **삭제 후 남은 고유 영상** | **7,739** |

첫 프레임 dHash 거리 분포를 실제로 찍어보면 `0~5` 구간에만 값이 몰려 있고 그 이상은 존재하지 않아, 임계값 근처의 애매한 오탐 없이 깔끔하게 갈렸습니다.

## 사용법

```bash
pip install pillow numpy

# 1) dry-run: 무엇이 삭제될지만 확인 (기본값, 실제로 지우지 않음)
python3 dedup_gifs.py /path/to/gif/folder

# 2) 실제로 macOS 휴지통으로 이동 (rm이 아니라 Trash로 이동하므로 되돌릴 수 있음)
python3 dedup_gifs.py /path/to/gif/folder --apply
```

실행하면 어떤 파일이 왜(`exact-md5-dup-of:...` 또는 `perceptual-dup-of:...`) 삭제 대상인지 `dedup_plan.json`에 기록됩니다.

## 왜 완전삭제(rm)가 아니라 휴지통 이동인가

Perceptual hash 기반 판정은 통계적으로 매우 정확하지만 100%가 아닙니다. 되돌릴 수 없는 `rm` 대신 macOS Finder의 휴지통으로 이동시켜, 결과를 확인한 뒤 문제가 있으면 복구할 수 있게 했습니다.

## 요구사항

- Python 3.8+
- macOS (휴지통 이동에 AppleScript/Finder 사용 — 다른 OS에서는 `move_to_trash` 부분만 `send2trash` 같은 라이브러리로 교체하면 됩니다)
